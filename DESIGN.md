# Salary Desk design system

Job Desk's DESIGN.md and corresponding runtime implementation are the locked visual source (2026-11-11). The vendored [foundation manifest](docs/design-foundation.json) records exact palette, semantic role, elevation, typography, spacing, radius and motion values and the inspected source commit. Salary Desk builds independently; no sibling code or private job data is loaded at runtime. Markdown documents CSS and does not generate it.

The canvas/sidebar is #fbfaf9 / #111214, content field #f4f4f3 / #18191c, panel #ffffff / #26272b, and inset #f7f7f7 / #303033. Signal #f15a0f, deep signal #c6440a. Hairlines: 8% warm ink in light, 10% white in dark; inputs 14% ink / 16% white. All --desk palette values and shared semantic mappings are retained exactly. The previous Incubyte lime/green overrides are removed.

Geist titles/headings/UI use weight 500, reading text 400. Titles 24/30px, headings 18px, UI 14px, metadata 12px, body 15px. Line heights, tracking, 4px spacing base, 6/8/12/16px radius scale and 150/240/360ms timings match the manifest. Lucide stroke 1.75 with 16px control icons. Gutter 16px phone / 24px tablet and desktop. Salary data controls retain a 44px target for touch accessibility; the explicitly requested compact theme segments match the source 28px scale.

Panels use shadow-panel's fine hairline and shallow blur, with no extra prominent outer border. Wells use shadow-well. Raised primary/outline actions use Job Desk's inset highlight, hairline and short button shadows; hover lifts, pressed moves 1px/insets. Repeated row actions and segments stay quiet. Popovers use shadow-popover. No glow, gradients or page-wide motion.

Semantic additions for salary rows reuse existing roles: table-head=inset, selection=signal-soft; hover mixes panel/foreground at 4% so it stays distinct from the header. Shell canvas and content field use their actual Job Desk semantic roles. Retain top inset, top-left rounding, flush right/bottom and internal scrolling. Reading sections alone may cap width; tables/dashboard fill the panel.

Inspection resolved two source discrepancies deliberately: the old prose's wide 72rem cap conflicts with its runtime full-width shell and our approved geometry, so runtime/full-width wins. Orange signal/white small text does not reach 4.5:1; raised primary actions use the existing deep-signal swatch with white text (no new palette), while focus/identity/chart accents retain signal. Focus uses the same signal with a visible adjacent 2px outline rather than relying on a faint 15%-opacity halo. Quiet metadata on the page field uses foreground-2 where needed. These are accessibility corrections, not another palette direction.

Sidebar uses Motion, matching Job Desk's installed stack and fast synchronized color changes. Active indicators and theme segments slide using shared layout animation, reduced-motion compatible. Base UI/Animate UI Select supplies keyboard/typeahead, listbox semantics, anchored viewport-aware menus and selection motion. Small fixed lists use Select; no duplicate native selector. Filters remain drafts until Apply, including sort/group/page size.

The headcount pair uses equal 256px plot areas with the country legend beside the doughnut and no disclosure footers. Salary Overview uses four financial cards; employee count remains in the population line. Inner table headers are square beneath result headings. Charts are dashboard-only, theme-token aware, with exact text values and equivalent tabular data. Charts may only consume bounded server aggregates, never employee arrays. No historical or cross-currency monetary graph.

Run npm run design:check. It verifies every vendored value in the standalone manifest, semantic aliases, absence of obsolete branding/native selects and palette literals in components, and checks declared contrast pairs. It does not claim full WCAG compliance; Job Desk's subtle input boundaries and quiet labels still require contextual/manual review. The original reusable third-party notices remain in THIRD_PARTY_NOTICES.md.

## Sheet backdrops

The shared sheet retains the existing light-mode foreground/25 scrim. In dark mode it uses black at 40% opacity, following the source foundation's black-scrim approach rather than the near-white text foreground. This shades the underlying workspace while preserving blur, sheet surface, animation, dismissal and focus restoration.

## Presentation surfaces

The Presentation retains the shared canvas/panel/inset roles and type scale. Reading prose has a deliberate width limit; diagrams and source panels use the available article width. Navigation groups distinguish Workspace from Presentation. The Presentation is a multi-page assessment report and documented engineering case study. Each page uses the full content panel, shared report header, active page navigation, previous/next links and single-column report reading order. Headings sit above their prose; source explanations follow the code. Figures and code panels retain full available width while prose keeps a readable line length. Scope, implementation, decisions and verification have dedicated routes; source/artifact readers remain deeper inspection surfaces. The portfolio reference informs clarity and visual explanations without copying its single-page/modal composition. Diagrams are server-rendered SVG flowcharts with named edges, decision diamonds, explicit validation/conflict/cache branches and relational FK connections. They use existing semantic tokens and text equivalents; no diagram/chart runtime is added. A minimum diagram width preserves label readability, with keyboard-focusable horizontal scroll on constrained views. Selected code/table regions scroll horizontally with keyboard focus when needed. Dashboard doughnut renders at 208px inside the existing 256px country plot region; department charts retain 256px. Currency label/control use a grid inside the bottom-aligned wrapping form.

Report documents use a distinct paper-like sheet on the existing field surface: card fill, fine edge, restrained panel shadow, near-square corners and responsive document margins. The sheet is capped at 1280px on wide displays; figures use its available width. App actions and section navigation sit outside the sheet. Running document headers/footers identify the assessment and section. Reading text uses the established 15px body role with 18px section headings; theme tokens keep light and dark documents readable. This is on-screen document presentation, not a fixed-page PDF or a typing animation.

The report overview places the completed video directly on the document sheet, without a tinted card or extra inset padding. A compact title/duration row, fine player border with a small radius, quiet download links and a bottom divider keep it aligned with the report. Native browser controls, a small poster and preload=none are retained. The MP4 is a public GitHub release attachment, with the supplied Drive copy linked alongside; it is excluded from Git history and deployment uploads. Other report pages do not mount a media player or fetch salary data.
